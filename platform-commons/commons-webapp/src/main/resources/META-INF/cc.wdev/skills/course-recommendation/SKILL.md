# 课程推荐 Skill

## 目的

负责根据用户的学习目标和个人情况，从本地课程库中搜索、筛选和评审合适的学习课程。

## 工作流程

1. 理解用户的学习目标。
2. 提取用户的当前学习水平。
3. 识别用户偏好的学习方式。
4. 提取课程相关的约束条件，例如：
    - 技术方向
    - 学习难度
    - 学习时间
    - 课程语言
    - 课程类型
    - 是否需要实战项目
    - 其他用户明确提出的要求
5. 根据提取出的需求，构造课程搜索条件。
6. 调用 `searchCourse` Tool，从本地 Elasticsearch（ES）课程库中查询候选课程。
7. 对 `searchCourse` 返回的候选课程进行评审。
8. 根据用户需求对候选课程进行筛选和排序。
9. 给出最终课程推荐，并说明推荐理由。

## Tool

### searchCourse

用于从本地 Elasticsearch（ES）课程库中搜索课程。

**使用场景：**

- 用户明确要求推荐课程。
- 用户希望学习某项技术或知识领域。
- 用户希望查找符合特定条件的课程。
- 需要根据用户的学习目标获取候选课程。

**调用要求：**

- 在进行课程推荐时，应优先通过 `searchCourse` 获取真实课程数据。
- 搜索条件应尽可能来源于用户明确表达的学习需求。
- 可以根据用户需求组合多个搜索条件进行查询。
- 不得自行编造课程数据来代替 `searchCourse` 的查询结果。
- `searchCourse` 返回的结果仅作为候选课程，不能直接视为最终推荐结果。
- 获取候选课程后，必须进入课程评审阶段，再确定最终推荐结果。

**数据来源：**

`searchCourse` → 本地 Elasticsearch（ES）课程库

## 规则

- 必须先理解并提取用户的课程搜索需求，再调用 `searchCourse`。
- 用户没有提供足够的搜索条件时，可以根据上下文提取合理的默认条件，但不得虚构用户需求。
- 课程推荐必须基于 `searchCourse` 返回的真实课程数据。
- 严禁虚构课程 ID、课程名称、课程平台、课程价格、课程时长等业务信息。
- 不得将搜索结果简单按照 ES 返回顺序直接推荐给用户。
- 必须在评审阶段判断课程是否真正符合用户的学习目标、水平和约束条件。
- 如果搜索结果不足以判断课程是否适合用户，应明确说明信息不足。
- 如果 `searchCourse` 没有返回合适的课程，不得自行编造课程进行补充推荐。
- 最终推荐应优先考虑用户的学习目标和约束条件，而不是单纯按照搜索结果排序。

## 推荐原则

课程评审时，应重点考虑：

1. **目标匹配度**
    - 是否能够帮助用户实现当前学习目标。

2. **难度匹配度**
    - 是否符合用户当前技术水平。

3. **内容匹配度**
    - 课程内容是否覆盖用户需要学习的知识点。

4. **学习成本**
    - 课程时长、学习投入等是否符合用户约束。

5. **实践价值**
    - 是否包含项目、案例或实战内容。

6. **综合适配度**
    - 综合用户需求对候选课程进行排序。

## 输出要求

最终向用户推荐课程时，应尽量包含：

- 课程名称
- 推荐理由
- 与用户目标的匹配点
- 适合的学习阶段
- 必要时说明课程之间的区别

所有课程的业务信息必须来自 `searchCourse` 的实际返回结果。
