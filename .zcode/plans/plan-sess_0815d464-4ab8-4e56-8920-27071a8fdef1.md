# ReAct 智能体实现方案 v3（基于现有 Spring AI 体系扩展，本期不含 MCP）

## 一、项目 AI 架构深度解读（现状结论）

**三层结构，抽象清晰、能力基本齐全，缺"智能体循环"这一块：**

1. **commons-core 抽象层**（`cc.wdev.platform.commons.ai`）
   - `AiManager`：门面。按 `ModelConfig(name/serviceProvider/modelProvider/baseUrl/apiKey)` 经 `ChatModelFactory`（DeepSeek/OpenAI/DashScope 三家，`platform.ai.providers.*.enabled` 条件装配）创建模型，每次新建不缓存；按 `AiVectorStoreType` 选 `VectorStoreFactory`（ES 默认/PgVector/MariaDB）。
   - `AiUtils`：Advisor 工厂（`SessionMemoryAdvisor`+`TurnCountTrigger(20)` 压缩、`RetrievalAugmentationAdvisor`、`getDocumentRetriever`）、`processChatSpec`（userId/tenantId/conversationId 注入 advisor params 与消息 metadata）、`renderPrompt`。
   - 工具：`CommonTools`(@Tool)、`ToolCallbackResolver` 按名解析。

2. **system 业务域**（`cc.wdev.platform.system.ai`，表全在 `db_pgsql_schema_core.sql`）
   - `AiChatApiImpl` 是**组装核心**：`chatType` 分发 STATIC/CHAT/AGENT/KB → 组装 ChatClient（模型+工具+advisor+RAG）。AGENT 分支已能：加载 `AiAgentVo`（含 model/kb/toolNames/mcpServerIds 关系）→ 建模型 → 挂 SkillsTool+DB 工具 → 挂 Session advisor（短期记忆）→ 挂 KB RAG advisor → 渲染 systemPrompt + temperature。**但无智能体循环、未挂长期记忆；mcpServerIds 本期不接线（预留）。**
   - 短期记忆（**本次保持不动**）：`SessionMemoryAdvisor` + `SessionMetadataAdvisor`，事件流持久化到 `sys_ai_session` / `sys_ai_session_event`（`CustomSessionRepository`，含 tool_calls/tool 响应 JSON、TTL 60 天、`TurnCountTrigger(20)` + `SlidingWindowCompactionStrategy(maxEvents=10)` 压缩、乐观锁版本控制）。
   - 长期记忆：`AutoMemoryToolsAdvisor`+`AutoDreamAdvisor`（spring-ai-agent-utils，文件 markdown 按 租户/用户 目录隔离，模型自主调用记忆工具），**目前只接在 STATIC 路径**（`applyMemoryAdvisor`），本期接入 AGENT 路径。
   - RAG：`AiHelper.resolveDocumentRetriever(kb)` 已封装 租户过滤 + topK/相似度 + 可选 rerank，`sys_ai_kb/item/chunk/task` + 异步向量化任务齐全。
   - MCP：服务端就绪（`one-mcp-server` @ `/api/mcp`，API Key 鉴权）；客户端本期不做。
   - 控制器：`AiChatWebController` `/api/v1/ai/chat/*`（@Authenticated，SSE 端点 `/chat/stream` 返回 `Flux<String>`）；`AiAgentPltController` `/api/v1/sys/ai/agent/*`（@PreAuthorize `dev:ai:config:agent`）。
   - 已知笔误：app-server 配置 `platform.ai.memory.path: file:../../tools/ai/memory`，实际目录是 `tools/agent/memory`。

**已确认选型**：① 自研 ReAct 循环；② 短期记忆**保持现有 Spring AI Session 体系不变**；③ RAG = Advisor 预检索 + 检索 Tool；④ MCP 本期忽略。**数据库零改动**（全部复用现有表）。

## 二、实施内容

### Phase 1 — ReAct 循环引擎（commons-core，可复用抽象）

新增包 `cc.wdev.platform.commons.ai.agent`：

- **`ReActAgent`**（builder 风格，与项目一致）：
  - `ReActAgent.builder().chatClient(...).maxIterations(10).build()`
  - `AgentResult call(String prompt)` 阻塞式；`Flux<String> stream(String prompt)` 流式（每步发 JSON 事件）
  - **循环实现（关键约束：必须走 ChatClient spec 而非裸 ChatModel）**——这样 logging/context/session/长期记忆 advisor 链全部继续生效，短期记忆由 `SessionMemoryAdvisor` 自动读写（历史注入 + 事件持久化 + 压缩），ReActAgent 自身不管理历史：
    1. 组 spec（历史由 Session advisor 注入）→ `spec.call().chatResponse()`
    2. 响应含 `toolCalls` → 逐个 `ToolCallback.call(args, toolContext)` 执行 → 构造 `ToolResponseMessage` → 通过 `.messages(...)` 追加进下轮 spec → 继续循环
    3. 无 toolCalls → 得到最终回答，循环结束
    4. 达到 `maxIterations`（默认 10，`AiConstants.MAX_AGENT_ITERATIONS`）→ 追加一条"基于以上观察，直接总结回答"强制收尾
- **`AgentEvent`**：`{type: THOUGHT|TOOL_CALL|TOOL_RESULT|ANSWER|FINAL|ERROR, step, toolName, toolArgs, toolResult, content}`，SSE 序列化单元
- 中间 Thought/Action/Observation 的留痕复用 `sys_ai_session_event`（Session 机制自动持久化），**不新增表**

### Phase 2 — RAG 检索工具 + 长期记忆接入（system-impl）

- 新增 `system/ai/tools/KnowledgeTools.java`：
  - `@Tool(name="search_knowledge_base")`，参数 `@ToolParam String query`、可选 `topK`
  - 实现委托 `AiHelper.resolveDocumentRetriever(kb).retrieve(query)`（租户过滤+rerank 全复用）；kb 由 ToolContext 传入（`processChatSpec` 已有 toolContext(userId) 先例，扩展为 `Map.of(USER_ID,.., KB_ID,..)`）
  - 仅当 agent 配置了 KB 时注册该工具；`applyRagAdvisors(builder, agent)` 保留（每轮预检索兜底）
- 长期记忆：AGENT 分支复用现有 `applyMemoryAdvisor(builder)`（`request.getWithMemory()` 控制，默认开）——文件式记忆工具在 ChatClient advisor 链中生效，租户/用户目录隔离逻辑原样复用

### Phase 3 — SSE 事件流与端点

- `AiChatApi` 新增 `Flux<String> chatAgentStream(SimpleChatRequest)`；`AiChatWebController` 新增 `POST /api/v1/ai/chat/agent/stream`（@Authenticated，`produces=TEXT_EVENT_STREAM`），返回逐步 `AgentEvent` JSON + 最终流式 ANSWER；旧 `/chat/stream` 行为不变，前端渐进迁移
- 系统提示词增强：AGENT 组装时在 `agent.systemPrompt` 后追加 ReAct 引导段（先思考、选工具、基于观察作答、能直接回答时不调工具、记忆操作静默等约定沿用 skills/memory 文档）

### Phase 4 — 配置修正 + 测试

- 修笔误：app-server `application-development.yml` 的 `platform.ai.memory.path` / `platform.ai.skills.paths` 由 `tools/ai/*` 改为 `tools/agent/*`（与 3717a93 实际目录一致）
- `AiConstants` 新增：`MAX_AGENT_ITERATIONS=10`、agent 事件/工具上下文 key
- 测试（遵循 AGENTS.md：优先 mock，不依赖外部中间件）：
  - commons-webapp：`ReActAgentTests`——mock ChatModel 返回"带 toolCalls → 无 toolCalls"两跳序列 + mock ToolCallback，验证循环/迭代上限/消息拼装
  - `KnowledgeToolsTests`——mock DocumentRetriever 验证输出格式
  - 手动验证：`bootRun` 后用 curl 打 SSE 端点，走通 普通工具 + KB 工具 链路

## 四、风险与对策

1. **Session 与 ReAct 中间步骤**：工具调用中间消息会进入 session 事件流并由压缩策略裁剪；实现时验证下一轮对话回放的消息拼装符合预期（若上下文膨胀，利用现有 `archived` 字段归档中间事件）。
2. **`internalToolExecutionEnabled` 边界**：手动循环要求模型响应返回 toolCalls 而非自动执行；不同 provider 表现有差异（DeepSeek/OpenAI 均支持禁用自动执行），实现时以两跳 mock 测试锁死行为。
3. **安全红线遵守**：新端点全部 @Authenticated；不触碰 /exchange；长期记忆路径按 tid/uid 隔离（现状已有）；工具执行结果截断防 prompt 爆炸（复用 DEFAULT_CHUNK_LIST_LIMIT 类上限思路）。

## 五、实施顺序

Phase 1（循环引擎，先用普通工具端到端跑通最小 ReAct 智能体）→ Phase 2（KB 检索工具+长期记忆）→ Phase 3（SSE 事件流）→ Phase 4（配置+测试）。每个 Phase 独立可验证；MCP 客户端作为下一期扩展点（`CustomMcpClientManager` 预留位置在 `system/ai/support` 包）。
